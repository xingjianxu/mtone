# 合并前全量回归与文档发布

在得到合并授权后，先验证拟合并的**完整 Git 树**，再合入 `master`。同一棵树只需在合并前跑一次全量回归；`master` 的 Documentation 工作流重新构建文档，不再跑这套回归。此流程不发布 npm。

## 推荐：授权后统一使用合并入口

1. 先整合当前远端 `master` 和待合并改动，准备好最终提交，审阅并保持工作树干净。需要能向 `github.com/xingjianxu/mtone` 推送的 Git 凭据，以及同一仓库的 GitHub CLI 读取权限。
2. 用准备候选时确认的远端 `master` SHA 执行下列命令。第三个参数可传本地提交 SHA 或引用，省略时用 `HEAD`：

   ```sh
   node scripts/merge-verified.mjs --expect-master <已核对的远端-master-SHA> [候选]
   ```

3. 入口以完整候选提交 SHA 命名 `release-candidate/<SHA>`。如果同名分支已验证了同一提交，重试会复用，不会再次推送或触发回归。入口验证候选的 Git 树，等待该分支、提交及运行尝试的 **Full regression** 成功（不限于工作流摘要）。它检出该事件的指定 SHA，运行原有类型、单元、文档、包和浏览器检查，并拒绝测试或构建改写受跟踪文件。候选运行不会部署。
4. 回归通过后，入口再次核对候选分支和远端 `master`。只有远端仍是指定基线且可以快进，才会执行普通非强制推送。Git 推送前核对服务器通告的旧 SHA，避免把并发更新误当成本次合并的基线；可执行的本地 `pre-push` hook 仍会运行。结束时打印精确提交的检查链接和按 `master`、提交 SHA 筛选的查询命令，不代表部署已完成。

每次等待最多约一小时。失败、超时、分支变化或权限拒绝不会绕过门禁。已创建的候选分支可保留作证据和重试，不会被脚本强推、删除或更新为其他提交。如果 `master` 已是候选 SHA，重试只输出追踪入口。若分支在等待期间变化，把新基线整合为新的候选再验证。

## 保护分支、运行缺失与首次启用

如果 `master` 受保护不允许直推，在同仓库候选分支（也可与普通 PR 分开）完成同样的全量验证，再通过获授权的 PR 路径合并。合并提交、squash 或 rebase 可产生新 SHA，但最后的**完整 Git 树**必须与已通过的候选完全相同。目标分支、冲突解法或 PR 内容变化导致树变化，要验证新候选。不要为绕开分支规则改用强推。可通过脚本先创建/等待候选；若普通推送被分支规则拒绝，现有成功运行仍可用。

GitHub 不一定会为使用内置 `GITHUB_TOKEN` 发起的推送创建新的运行，脚本也不会自行补一次。若确实没有运行，先核实候选分支和 SHA，再从 Documentation 手动对该分支运行一次，检查 SHA 与候选一致；之后可以重跑入口，不要重复启动同一候选。若只缺应用权限或网络，请修复后重试；不要回退到未经验证的推送。

首次启用新版流程时，候选本身必须包含新版工作流及入口脚本，优先通过受信任候选分支的推送触发。可由获授权的维护者一次性创建同仓库候选并核实其真实全量回归（还未在 `master` 可用时不依赖 dispatch）。在验收前不要推进 `master`；此前其他提交的回归不能代替最终脚本版本的验证。

## 核验 Pages

合并成功后，`master` 的 Documentation 自动运行。它优先查找相同提交的验收，再查最近成功运行中同树的候选；候选必须来自本仓库、指定候选分支和同一个工作流，且对应 run attempt 的 **Full regression** 确实完成。匹配不到、GitHub API 返回错误或当前 `master` 变化均不会发布。通过后从当前事件提交构建并上传本站产物，不下载候选运行中的文件。最后核对成功的 Pages 部署对应目标 SHA，以及线上 `llms.txt` 与该提交一致。

没有有效证据时，先核实候选和目标树；如果只找不到较早的同树证据，请从仍正确的树生成新候选并等待通过，再针对当前 `master` 手动重跑 Documentation。若合并事件由于认证方式等原因未创建运行，也可手动针对当前 `master` 运行，验证规则不变。不要手动上传未通过验证的站点或对过时提交强制部署。

## 权限边界

这是发布门禁，不会自行阻止仓库在 GitHub 上合并 PR；合并前须由获授权的整合者核对成功的候选与预期合并树。如需在仓库层强制合并审批、禁止未审核推送或保护工作流、验证脚本及测试变更，应由仓库管理员设置分支规则和代码所有权。本变更不修改任何仓库或 Pages 环境设置。

同仓库 `release-candidate/**` 是受信任的整合者路径，不面向外部 PR 或其他不受信任的代码。候选工作流运行仓库代码，候选命名空间的写入者以及对验证定义的审核须受控；GitHub 运行记录不能识别被故意削弱的测试。外部贡献应先由维护者审阅，再进入同仓库候选。候选只授予只读权限，不注入仓库秘密；只有 `github-pages` 部署作业授予 Pages 和 OIDC 写权限。
