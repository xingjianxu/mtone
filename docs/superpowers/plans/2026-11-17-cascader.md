# Cascader implementation plan

Goal: add compact hierarchical selection in mtone without Ant Design runtime dependencies.
Architecture: Cascader/CascaderPanel share a selection state controller and column view; existing Base UI Popover handles portal positioning and dismissal. Path arrays preserve string/number identity. Multiple values are selectable leaf paths, while parent labels are presentation only. Lazy loading returns children and rejects to retry; obsolete responses must not affect new options.

- [x] Write failing interaction tests for paths, controlled state, disabled nodes, parent cascade, search, keyboard, and async loading.
- [x] Implement state/view in packages/mtone/src/cascader.tsx and scoped CSS; register exports.
- [x] Add examples/catalog and regenerate llms; include package smoke checks.
- [x] Add three-engine browser fixtures and geometrical/keyboard/mobile regressions, wire existing CI.
- [x] Independent review, fix with regressions, run full unit/type/docs/package checks.

Review focus: disabled ancestors, numeric/string keys, stale async responses/retries, IME and focus after dismissal, popup size/long labels. Limits: search only known data, fixed-size loaded columns (no virtualization), no JSX Option API or arbitrary field-name mapping. No remote writes or npm publication.
