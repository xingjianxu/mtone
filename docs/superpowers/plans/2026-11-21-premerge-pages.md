# Pre-merge regression and exact-tree Pages design

- Keep the existing Documentation workflow ID, all regression steps, tests, and Pages environment. Run the full gate only on a reviewed same-repository `release-candidate/**` branch push or explicit dispatch. Check out the immutable event SHA before testing. Require clean tracked files afterward so regenerated reference changes fail the pre-merge check.
- On a master push or manual master retry, verify the exact checkout and find a GitHub-recorded, completed successful run of this workflow on a same-repository candidate ref. Verify the actual completed regression job and explicit checkout/tracked-files steps in that run attempt. Use exact commit lookup first, then allow a different commit only if GitHub's commit object has the identical complete Git tree. Do not accept PR/fork logs/artifacts, skipped jobs, stale attempts, mixed repo IDs or similar workflow names.
- After verification, rebuild Pages from master without browser tests and upload only that build's artifact. Deploy from the existing `github-pages` environment with narrowly scoped write permissions and confirm that the target SHA is still the master ref before publishing. Unknown/failed proof is an error; it makes no site change.
- In `docs/CONTRIBUTING-CI.md` (link from `AGENTS.md`) document making an integration candidate, waiting for its verified run, promoting that immutable candidate via simple fast-forward or a PR merge that yields the same tree, recovery, bootstrap and settings boundaries. Ordinary pull requests can use a separately named candidate with the exact reviewed result; do not run branch and PR duplicates.
- TDD in `tests/docs-regression-proof.test.mjs` around the proof helper in `scripts/verify-docs-regression.mjs`; include no-proof fail-closed bootstrap, direct exact SHA, identical trees across commit hashes, wrong tree, foreign repo, candidates only, skipped/untrusted job steps, and API errors. Check behavior with positive and negative mocked REST responses; preserve baseline workflow step coverage mechanically; actionlint where available; verify typecheck, npm tests, docs build, package smoke and generated reference.
