# Tree enhancement implementation plan

Goal: Keep the existing mtone tree API working while adding common selection, check, load, visual, directory, drag and virtual-list capabilities.
Architecture: Extract Tree from data.tsx, keep its re-export. Pure immutable model handles normalization, indexes and disabled-boundary check conduction. React layer controls interaction, asynchronous loading, accessible flat tree rows and fixed-height virtualization. No new runtime dependency.
Constraints: Preserve legacy single selection/expanded aliases, use neutral mtone styling and existing Checkbox, no npm publishing. Drag/drop reports intent and never mutates supplied data. Virtual rows require fixed heights; custom motion/TreeNode JSX/useTree compatibility are not promised.

- [ ] Model tests then implementation: normalization, disabled-boundary conduction, parent expansion, flattened ARIA positions.
- [ ] Interaction tests then implementation: old API, controlled state, multiselect/checks, async retry and deduplication, keyboard/focus recovery, directory actions, drag rejection, virtual scroll ref.
- [ ] Document and demo each supported API and explicit limitations, regenerate llms.
- [ ] Independent review, full local suite/typecheck/build/tarball and three-browser fixture including narrow layout.
- [ ] Authorized push and complete CI, merge only when green, verify exact deployed reference.
Review focus: stale asynchronous completions, disabled nodes, controlled empty lists, removed focused nodes, virtual focus outside mounted range and drop into own descendants.
