# Menubar

## Scope

Add an mtone-styled desktop command bar inspired by Mantine Menubar, without API compatibility. Reuse Base UI Menubar for roving focus and Menu for semantic menu behavior; reuse DropdownSurface for sizing, portal styling and collision handling. Do not nest the public Dropdown (a dialog popover) around semantic menus.

Public API follows existing data-driven Menu: `menus` with stable keys, label/icon/disabled/items and per-menu width/align; bar-level openKey/defaultOpenKey/onOpenChange, onSelect, trigger and loop. Each bar is one tab stop. Popup width remains content-based unless overridden. Narrow screens scroll the trigger row rather than wrapping keyboard order. Direction follows Base UI DirectionProvider.

Shared MenuEntry adds checkbox and radio-group options with callbacks separate from command onSelect. Menu portals remain mounted while hidden so uncontrolled options retain state. Hover mode uses an owner marker across portals and cancellable 180ms dismissal to permit crossing popup gaps. Focus restoration is suppressed during sibling switching, preserved on final dismissal.

## Verification

Unit tests cover keyboard entry/return, nested selection, controlled opening, hover switching/dismissal/gap traversal, outside click/reopen, RTL and loop, persisted checkbox/radio state. Package smoke checks installed export/types/SSR. A three-engine Playwright fixture covers real pointer/focus/viewport behavior; local engines are unavailable and system Chromium is blocked by sandbox socket/ptrace restrictions, so browser checks remain a CI gate.

No npm publication, remote push or master merge is part of this implementation step.
